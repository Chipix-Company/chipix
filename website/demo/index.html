My mental model · derived from your description and clarifying answers

UART APB Controller

An 8-bit asynchronous serial transmitter/receiver that exposes a 32-bit APB slave interface for register access. The block buffers data with 16-byte synchronous FIFOs on both transmit and receive paths, generates its own baud clock from a fractional divider, and raises an interrupt when the RX FIFO crosses a programmable threshold.spec §2.1

Functionality

  • APB slave reads/writes to four 32-bit registers: CTRL, BAUD, DATA, STAT
  • Transmits 8-bit data with optional parity (none / even / odd, configurable via CTRL[6:5])
  • Receives 8-bit data; flags framing and parity errors in STAT
  • Generates irq when RX FIFO level crosses a programmable threshold (default 8)
  • Baud rate updates only honoured when both FIFOs are empty (per your decision)

Experimental insights

I noticed your spec leaves oversampling factor unspecified. I'm defaulting to 16× at mid-bit (standard), but flag this — some industrial systems run 13× to save power. Want me to expose this as a register field?

I also see the spec mentions "back-pressure" on RX once — but the FIFO can't really push back over a UART line. I'm treating that paragraph as informational. Confirm if you wanted hardware flow control (RTS/CTS) instead.
